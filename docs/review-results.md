# Local review results

Set `review.results_dir` in `~/.config/decky/config.toml` to read local review
results in the review inbox, or set `DECKY_REVIEW_RESULTS_DIR`:

```toml
[review]
results_dir = "~/.local/share/decky/review-results"
```

This is opt-in and disabled when unset or empty. Unset the setting to disable it.
The server reads files on each inbox refresh. Use the command below to generate
results; an external scheduler decides when to run it. Nothing is posted to GitHub.

The collapsed PR row shows the primary risk. Expand it for the three summary
fields and any second opinion with its own risk and reviewer. If `head_sha`
differs from the current PR head, both views mark the result outdated; it stays
visible for context and should be regenerated by the producer.

## Generate a result

```sh
decky review-result write example/demo 101
decky review-result write example/demo 101 --force
```

The command fetches metadata, the head SHA, and the diff through `gh`. It skips
when `results_dir` is unset, the PR is a draft, or a valid result already matches
the head. `--force` bypasses the matching-head skip. It checks the head and draft
state again before writing, so a changed PR requires another run. Failures leave
any existing result intact. New directories use mode `700`; files use `600` and
are replaced atomically with a temporary file and rename.

Configure argv arrays, never shell command strings. Commands receive a prompt
on stdin and must print only one JSON object to stdout and exit zero. Each runs
in an empty temporary working directory. Primary output:
`{"risk":"low","summary":{"what_changed":"...","why":"...","what_to_check":"..."}}`.
Second output: `{"risk":"medium","summary":"..."}`. Risks and strings obey the
version 1 constraints below; Decky supplies the SHA, timestamp, and reviewer labels.
Malformed, oversized (over 256 KiB), failed, or timed-out responses write nothing.

```toml
[review]
results_dir = "~/.local/share/decky/review-results"
reviewer_command = ["codex", "exec", "--model", "gpt-6.1-sol", "--sandbox", "read-only", "--ephemeral", "--skip-git-repo-check", "-"]
second_reviewer_command = ["claude", "--print", "--model", "opus", "--output-format", "text", "--tools", "", "--no-session-persistence"]
reviewer_label = "Primary reviewer"
second_reviewer_label = "Second reviewer"
reviewer_timeout = 300
large_diff_lines = 1000
max_diff_bytes = 100000
sensitive_patterns = []
```

These non-interactive examples use the installed CLIs' help flags. `opus` selects
Claude's current Opus model. Use authenticated CLIs available on `PATH`, or
absolute executable paths. Plain/text output is intentional: JSON event streams
and CLI response envelopes do not match the reviewer contract. Prompts request
JSON; responses still pass the version 1 validator before writing.

The shown labels, timeout (seconds per reviewer), added-plus-deleted line threshold,
diff byte cap, and extra patterns are the defaults. Both command arrays default
to empty and must be configured before use. Each setting also supports its
`DECKY_REVIEW_<UPPERCASE_KEY>` environment variable; arrays use JSON string arrays.
Extra `sensitive_patterns` are case-insensitive regular expressions added to the
defaults. Defaults match auth, credentials/secrets/passwords/tokens, billing/payments,
migrations, data rewrites/backfills, sending, approvals/permissions, and CODEOWNERS
only in changed file paths and the PR title, at word boundaries (including
underscore separators). PR bodies and diff text do not trigger sensitive-area
matching. These heuristics can flag harmless paths or titles too.
At or above `large_diff_lines`, or when context is truncated, a second opinion is
also required. A flagged PR fails without `second_reviewer_command` configured.
Only `max_diff_bytes` of diff and 20,000 body characters enter the prompt;
truncation is disclosed to reviewers. All PR text is explicitly untrusted data.

An external scheduler can call `decky review-result write OWNER/REPO NUMBER`
after a PR becomes ready for review and whenever a ready PR's head changes.
Call once per PR; Decky does not install a scheduler or enumerate ready PRs.
Use `--force` to regenerate for a new ready event on an unchanged head.

## Version 1 format

Use one UTF-8 JSON file per PR, directly inside the configured directory:
`<owner>+<repo>-<number>.json`. Lowercase owner and repository names. For example,
PR 101 in `example/demo` uses `example+demo-101.json`. The `+` separator cannot
occur in GitHub owner or repository names.

```json
{
  "version": 1,
  "head_sha": "0123456789abcdef0123456789abcdef01234567",
  "risk": "medium",
  "summary": {
    "what_changed": "Add a report export button.",
    "why": "Let readers save a local copy.",
    "what_to_check": "Try exporting an empty report."
  },
  "reviewer": "Primary reviewer",
  "generated_at": "2026-11-07T12:00:00Z",
  "second_opinion": {
    "reviewer": "Second reviewer",
    "risk": "high",
    "summary": "Check that exports include only the intended fields."
  }
}
```

All fields except `second_opinion` are required. Omit it or use `null` when there
is no second opinion. Both risks must be `low`, `medium`, or `high`. `head_sha`
must be the full 40-character hexadecimal PR head commit. `generated_at` is an
ISO 8601 timestamp with a timezone. Reviewer labels must contain 1–200 characters;
summary strings must contain 1–10,000 characters after trimming whitespace.
Unknown fields are ignored; unsupported versions are ignored.

`GET /api/inbox` adds a valid result to its PR row as `review_result` (the
validated fields above, without unknown fields) plus `outdated`, which is `true`
when `head_sha` differs from the PR's current head commit. PRs without a valid
result have no `review_result` key.

Files must be regular files, at most 256 KiB. Missing, unreadable, malformed,
oversized, or symlinked files are quietly ignored. The reader uses a flat filename
and does not follow symlinks from result files. Producers should write a temporary
file in the directory and atomically rename it to avoid partial reads.

## Private data

Result text stays in local files and is served as plain text through the existing
inbox API to inbox viewers. The reader makes no network calls and writes nothing
to GitHub. Results may contain private PR information: keep the directory private
(for example mode `700`, files `600`), and apply the same access controls as the
rest of the inbox if exposing the server through a proxy. Decky does not copy
results into browser storage. The writer sends PR descriptions and diffs to the
configured reviewer commands, which may send them to remote model providers and
keep their own logs. Choose commands and provider data policies appropriate for
the repositories being reviewed. Prompt instructions do not sandbox commands;
configure their permissions and tools accordingly.
